# 2026-08-15：工作沙盒内聊天框分组（session groups）设计

## 背景

dsh-myagent 定位为「反向在 Agent 里集成类 VS Code 的文件管理系统」。当前侧栏只有
「工作沙盒 → 会话（聊天框）」两层结构。用户希望在**每个工作沙盒内**再增加一层
**命名分组（文件夹式）**，用于组织聊天框。

已确认需求：

- 形态：**扁平命名分组**（不嵌套）。
- 默认分组：每个工作沙盒自动有一个**默认分组**，新会话自动进入；默认分组**不可删除、可重命名**。
- 未分组聊天框：不显示独立“未分组”区，全部由默认分组兜底。
- 操作：新建/重命名/删除分组、折叠/展开分组、拖拽调整分组顺序。
- 删除分组：弹窗让用户选择组内聊天框去向（默认分组 / 其他分组 / **归档会话**，归档是当前宿主的删除等价能力）。
- 移动聊天框：支持**拖拽 + 行内“移动到分组”菜单**。
- 数据存储：写入每个工作沙盒根目录下的隐藏文件 `.myagent/groups.json`，随项目走。

## 数据模型

### 文件位置

```
<工作沙盒根>/.myagent/groups.json
```

`.myagent` 目录在文件树中隐藏，不作为普通文件展示。

### JSON 结构

```json
{
  "version": 1,
  "defaultGroup": {
    "id": "default",
    "name": "默认分组"
  },
  "groups": [
    {
      "id": "g_xxxxxxxx",
      "name": "工作",
      "sessionIds": ["s3", "s7"]
    },
    {
      "id": "g_yyyyyyyy",
      "name": "项目A",
      "sessionIds": ["s2"]
    }
  ]
}
```

语义：

- `defaultGroup`：默认分组元数据；**成员不显式存储**，等于“该工作沙盒下未进入任何命名分组的会话”。
  这样新会话天然落在默认分组，无需每次写入。
- `groups`：命名分组数组，**数组顺序即侧栏展示顺序**；默认分组固定显示在最上方，不参与排序。
- `sessionIds`：命名分组内的会话 id，**顺序沿用宿主工作沙盒的扁平顺序**，不在 JSON 中重复维护。
  因此组内拖拽排序继续走宿主 `insertSessionBefore`，分组数据只负责“归属”。

### 与会话合并规则

- 展示时，命名分组显示 `w.sessionIds` 中属于该组的会话；默认分组显示“不在任何命名分组中的会话”。
- 新会话出现（`w.sessionIds` 新增且不在任何命名分组中）→ 自动归入默认分组，无需写盘。
- 归档会话（`archivedSessionIds`）在分组中隐藏，与现有行为一致。

## 操作与数据流

### 读取

1. `WorkspaceBrowser` 增加 `api` 依赖（由 `SidebarComposite` 从 `Composed` 传入）。
2. 当前 root 变化时，通过 `Api.read(".myagent/groups.json")` 读取。
3. 文件不存在 / JSON 无效 / 读取失败 → 内存中使用「默认分组」兜底，不阻塞 UI。
4. 读到版本号 `version` 作为写回 CAS 的 `expectedVersion`。

### 写入

所有写操作统一走 `Api.write(".myagent/groups.json", content, expectedVersion)`：
- 写前先读当前文件拿最新版本（或使用本地已缓存版本）。
- 若返回 409（版本过期）→ 重新读取、合并本地操作、重试一次；仍失败则提示用户刷新。
- 写失败（沙箱拒绝、路径异常等）→ 用现有 `describeApiError` 展示错误。

### 分组管理

| 操作 | 行为 |
|---|---|
| 新建分组 | 工作沙盒行 hover 出现“新建分组”按钮 → 弹 PromptModal 输入名称 → 追加到 `groups` 末尾 |
| 重命名分组 | 分组行 hover 出现重命名按钮 → 更新 `name` |
| 删除分组 | 弹 ConfirmModal/选择 Modal：选择组内会话去向（默认分组 / 其他命名分组 / **归档会话**）→ 更新数据 |
| 折叠/展开 | localStorage 记录 `fm.group.collapsed`（分组 id 集合），与工作沙盒折叠同模式 |
| 调整分组顺序 | 分组行 HTML5 拖拽，仅命名分组参与排序；默认分组固定顶部 |

### 会话移动

- **拖拽**：会话行可拖入目标分组行（`drop` 到分组行 = 移入该组）；组内拖拽继续使用现有
  `insertSessionBefore` 排序。
- **菜单**：会话行 hover 出现“移动到分组”按钮 → 弹出分组选择菜单（列出默认分组 + 所有命名分组）。
- 移动到命名分组：从原分组（或默认）移除，加入目标分组 `sessionIds`，并调用
  `insertSessionBefore(workspaceId, sessionId, undefined)` 追加到宿主扁平顺序末尾，使目标分组内按当前顺序显示。
- 移动到默认分组：从原命名分组移除即可（默认分组成员隐式）。

## UI 结构

```
工作沙盒 A
├─ [新建分组]
├─ ▾ 默认分组 (2)
│   ├─ 会话 1
│   └─ 会话 2
├─ ▾ 工作 (1)
│   ├─ 会话 3
│   └─ ...
├─ ▸ 项目A (0)
└─ ...
```

- 分组行：文件夹图标 + 名称 + 会话数；hover 显示“重命名 / 删除”操作按钮。
- 会话行：沿用现有状态点 + 名称 + hover 操作；新增“移动到分组”按钮。
- 拖拽样式沿用现有 `fm-wb-drop-before/after` 插入线；分组行作为会话 drop 目标时高亮。

## 错误处理

- `groups.json` 损坏：按空数据（仅默认分组）渲染；用户下一次写操作时以当前内容覆盖。
- 写版本冲突（409）：自动重读合并重试一次；仍失败则提示“分组保存冲突，请刷新后重试”。
- 文件系统写入被沙箱拒绝：展示 `describeApiError` 的文案，不静默失败。
- 删除分组时若选择“归档会话”：调用宿主 `archiveSession` 将组内会话归档（从列表隐藏，保留日志）。

## 文件树隐藏

- `FileService.tree` 在根目录过滤掉 `.myagent` 条目，避免用户看到/操作隐藏元数据目录。
- 命名分组数据仍通过现有 `/api/myagent/read|write` 读写（内部路径不做额外拦截，本地用户可手动编辑，损坏时按兜底处理）。
