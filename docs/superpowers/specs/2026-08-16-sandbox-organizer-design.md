# 2026-08-16：工作沙盒智能整理（Sandbox Organizer）设计

## 背景

dsh-myagent 当前已有“工作沙盒 → 分组 → 聊天框”的树形结构，但缺少语义层的组织能力。
用户希望引入一个**全局常驻的独立子 agent**，负责：
- 记录工作沙盒中所有条目的父子树关系；
- 为每个工作沙盒、每个分组、每个聊天框维护一句“项目简述/标注”；
- 在一键整理时，根据这些标注给出“整理前后差异”，由用户勾选后执行。

## 目标

1. 新增一个全局常驻子 agent（1M 上下文、干净、无工具、不受已有规则限制）。
2. 每个实体（工作沙盒/分组/聊天框）都有一句可人工编辑、可被 agent 更新的一句话标注。
3. 侧栏“工作沙盒”标题栏新增“一键整理”按钮；点击后隐藏具体内容，展示差异交互框。
4. 差异交互框展示“与上一版的改动”，支持逐条勾选 + 全选，应用勾选项后执行整理。
5. 聊天框获得标题的同时，顺带生成一句项目简述。

## 非目标（暂不做）

- 上下文长度达到 40% 时自动更新简述。
- 读取完整会话内容（只用标题 + 简述）。
- 给常驻子 agent 挂载任何工具。

## 总体架构

```
┌─────────────────────────────────────────────────────────┐
│                     dsh-myagent 插件                      │
│                                                         │
│  UI: 重命名弹窗(标题+简述) / 一键整理按钮 / 差异交互框     │
│                                                         │
│  标注存储: .myagent/annotations.json  ←→  UI 直接读写     │
│       │                                                 │
│       └── 同步注入 ──► 全局常驻子 agent（1M 上下文）      │
│                         （干净 agent，无工具）             │
│                                                         │
│  标题/简述生成: 复用 dsh 现有 session-title 机制           │
└─────────────────────────────────────────────────────────┘
```

## 数据模型

### 标注文件

路径：`<工作沙盒根>/.myagent/annotations.json`

```json
{
  "version": 1,
  "workspaces": {
    "<workspaceId>": {
      "id": "<workspaceId>",
      "brief": "一句话说明这个工作沙盒是做什么的",
      "updatedAt": "2026-08-16T00:00:00.000Z"
    }
  },
  "groups": {
    "<groupId>": {
      "id": "<groupId>",
      "workspaceId": "<workspaceId>",
      "brief": "一句话说明这个分组的用途",
      "updatedAt": "2026-08-16T00:00:00.000Z"
    }
  },
  "sessions": {
    "<sessionId>": {
      "id": "<sessionId>",
      "title": "会话标题",
      "brief": "一句话说明这个对话是干什么的",
      "updatedAt": "2026-08-16T00:00:00.000Z"
    }
  },
  "lastOrganizedAt": "2026-08-16T00:00:00.000Z",
  "lastPlan": {}
}
```

- `workspaces` / `groups` / `sessions` 分别存各层级的一句话标注。
- `lastPlan` 保存上一次应用后的整理计划快照，用于“与上一版的改动”对比。
- 该文件是 UI 可读写的权威副本；同时会同步一份摘要给常驻子 agent 上下文。

### 树结构

整理时使用的“当前树”来自现有数据：
- 工作沙盒（`WorkspaceView`）
- 分组（`.myagent/groups.json`，已有）
- 聊天框（`workspace.sessionIds` + 分组归属）

## 常驻子 Agent

### 创建与生命周期

- 使用 dsh 的 continuable subagent 能力（`ctx.subagents.startContinuable`）创建一个全局唯一、跨会话可续接的子代理。
- 若宿主当前不允许插件直接持有父 Agent，则使用宿主提供的等效持久化子代理机制，或降级为“按需创建 + 会话持久化”。
- Agent 的 system prompt 为独立定制的“工作沙盒整理员”提示词，**不继承任何已有全局规则**，**不注入任何工具**。

### 职责

1. 根据注入的“当前树 + 标注 + 标题/简述”理解每个实体的用途。
2. 在一键整理时，输出一份**结构化整理建议（JSON）**：
   - 聊天框建议移动到哪个分组；
   - 建议新建/重命名/删除/合并哪些分组；
   - 建议更新哪些实体的一句话标注。
3. 不直接修改文件、不调用工具；所有读写由插件完成。

### 上下文维护

- 插件在每次“一键整理”或“标注变化”时，把最新的树 + 标注快照作为消息发送给它。
- Agent 的 1M 上下文长期保留这些简短标签，足以支撑整理推理。
- 标注的权威副本始终在 `.myagent/annotations.json`，Agent 上下文只是同步视图。

## 一句话标注的生成与编辑

### 生成时机

- 复用 dsh 现有 session-title 机制：当聊天框从空白变成有实际内容并生成标题时，插件监听 `session/title` 事件，在同一路由下额外生成一句“项目简述”。
- 简述 Prompt 示例：
  > 根据该会话的标题和首条用户消息，用一句话说明这个对话是用于什么的，不要输出解释。

### 编辑入口

- 聊天框“重命名”弹窗：标题输入框下方增加“项目简述”输入框。
- 分组“重命名”弹窗：增加“分组简述”输入框。
- 工作沙盒“重命名”弹窗：增加“工作沙盒简述”输入框。
- 人工编辑后写入 `.myagent/annotations.json`，并同步给常驻子 agent。

## 一键整理流程

1. 用户点击“工作沙盒”标题栏右侧的“一键整理”按钮。
2. 插件收集当前全部工作沙盒树 + `.myagent/annotations.json` 标注。
3. 把快照作为消息发送给全局常驻子 agent，请求返回整理建议 JSON。
4. 插件把“建议后的树”与“当前树/上一版快照”做 diff，生成差异列表：
   - 新建分组 / 删除分组 / 重命名分组 / 合并分组
   - 聊天框移动（从 A 分组到 B 分组）
   - 各层级一句话标注的新增/修改
   - 数量变化（分组数、聊天框数）
5. 工作沙盒内容区切换为“差异交互框”：
   - 展示上述差异；
   - 每条差异前有勾选框；
   - 顶部有“全选/全不选”；
   - 底部“应用勾选项”按钮。
6. 用户确认后，插件按勾选项执行：
   - 移动聊天框（`moveSessionToGroup` + 宿主 `insertSessionBefore`）
   - 新建/重命名/删除/合并分组（`groups.json` 操作）
   - 更新 `.myagent/annotations.json`
   - 把新的快照写回 `lastPlan`
7. 执行完成后恢复工作沙盒具体内容展示。

## UI 改动

- `WorkspaceBrowser` 标题栏右侧新增“一键整理”按钮。
- 新增 `OrganizePanel` 组件：整理中状态 / 差异列表 / 全选 / 应用。
- `PromptModal` / `RenameDialog` 扩展支持“简述”输入框。
- 聊天框、分组、工作沙盒的现有重命名弹窗均增加简述字段。

## 错误处理

- 常驻子 agent 创建失败：提示“整理员初始化失败”，按钮保持可用但无法整理。
- Agent 返回非法 JSON：提示“整理建议解析失败”，允许重试。
- 应用部分勾选项失败：已成功的项不回滚，失败的项单独提示，并保留未应用差异。
- `annotations.json` 损坏：按空标注初始化，不阻塞整理。

## 测试

- `annotations.json` 的读写/合并/损坏兜底纯函数测试。
- diff 计算：新增/删除/移动/改名/标注变化的纯函数测试。
- 勾选应用：部分应用、全选、全不选的逻辑测试。
- UI 部分以 tsc + 手工验证为主（UI 测试地基后续补）。

## 范围

包含：
- `.myagent/annotations.json` 读写与纯函数
- 全局常驻子 agent 的创建/续接/整理请求
- 一键整理按钮 + 差异交互框
- 重命名弹窗的简述编辑
- 标题生成时顺带生成简述

不包含：
- 40% 上下文自动更新
- 完整会话内容读取
- 子 agent 工具能力
